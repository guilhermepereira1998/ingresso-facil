Ingresso Fácil.

API acadêmica para cadastrar eventos e participantes, emitir ingressos e registrar a entrada no evento.

Demonstração e API

A página online usa dados fictícios em memória. Para operar sobre o SQLite, execute o projeto localmente e utilize o Swagger em /docs. Não há pagamentos reais nesta versão.

Executar o projeto

Requisito: Python 3.10 ou superior. O pacote inclui iniciadores para Windows e Linux/macOS.

Windows

Execute iniciar.bat ou use:

python -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload
Linux / macOS

Execute sh iniciar.sh ou use:

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload

Site local: http://127.0.0.1:8000/site/
API e testes manuais: http://127.0.0.1:8000/docs

Modelagem

  • Eventos: nome, data e capacidade.
  • Participantes: nome e e-mail único.
  • Ingressos: vínculo com evento e participante, código UUID, estado de uso e criação.

Um evento possui vários ingressos. Um participante pode ter ingressos em eventos diferentes. A combinação de evento e participante é única.

Regras de negócio

  • A emissão respeita a capacidade cadastrada do evento.
  • Um e-mail não pode identificar dois participantes.
  • Cada participante pode ter um ingresso por evento.
  • Cada ingresso recebe um código UUID próprio.
  • Um ingresso utilizado não pode ser reutilizado nem reativado.

Rotas da API

MétodoRotaOperação
POST/eventosCriar evento
GET/eventosListar eventos
GET/eventos/{evento_id}Consultar evento
PATCH/eventos/{evento_id}Atualizar evento
DELETE/eventos/{evento_id}Excluir evento
POST/participantesCadastrar participante
GET/participantesListar participantes
GET/participantes/{participante_id}Consultar participante
PATCH/participantes/{participante_id}Atualizar participante
DELETE/participantes/{participante_id}Excluir participante
POST/eventos/{evento_id}/ingressosEmitir ingresso
GET/eventos/{evento_id}/ingressosListar ingressos do evento
GET/ingressos/{ingresso_id}Consultar ingresso
PATCH/ingressos/{ingresso_id}/usarRegistrar entrada
PATCH/ingressos/{ingresso_id}Atualizar uso (parâmetro utilizado na query)
DELETE/ingressos/{ingresso_id}Excluir ingresso

Respostas: 201 para criação; 200 para consulta e atualização; 204 para exclusão sem corpo; 400 para violações de regras; 404 para registros inexistentes; 422 para dados inválidos.

  • Davi Borges Kruger

    Partes 3 e 4

    3. Como funciona o banco de dados?

    Criamos três tabelas: eventos, participantes e ingressos. A tabela de ingressos conecta um evento a um participante e registra o código e se o ingresso foi utilizado.

    4. Como funciona a emissão de ingressos?

    Primeiro, cadastramos o evento e o participante. Depois, emitimos o ingresso informando os IDs dos dois. O sistema verifica se existem, se há vagas e se o participante já possui ingresso para aquele evento.

Escopo

O projeto fornecido foi integrado ao site. As quatro rotas de ingresso foram alinhadas aos caminhos do README. A limitação de concorrência da verificação de capacidade, indicada no material original, permanece: uso simultâneo em grande escala exige reforço da transação.

Não há autenticação, pagamentos ou leitor de QR code. A arte 3D é ilustrativa.
